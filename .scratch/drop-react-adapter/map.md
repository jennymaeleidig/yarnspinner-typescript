# Wayfinder map: drop the React adapter

Labels: wayfinder:map

## Destination

The package has no React code anywhere: `src/react/` is deleted, the `./react` subpath export and the React peer/dev dependencies are gone, and every consumer of the adapter — the browser demo and the Next.js host — runs against the vanilla runtime (`Dialogue` + `Transcript` + the package root). The core was already React-free; this effort removes the last React surface and re-homes what the adapter was pinning (tests, docs, examples) so nothing silently loses coverage. The SvelteKit host, already zero-React, is untouched.

## Notes

- Domain: this repo is a TypeScript Yarn Spinner 3.x parser/compiler/runtime, framework-agnostic core. Vocabulary from `CONTEXT.md` is binding (**Program**, **YarnProject**, **Dialogue**, **Transcript**). Coding standards: `CODING_STANDARDS.md`.
- Decisions already locked by the human (do not re-litigate): the adapter is dropped **entirely** — not deprecated, not behind a flag; `examples/browser` and `examples/nextjs-host` are **rewritten against the vanilla runtime**, not deleted; the core `YarnRunner` → `Dialogue` deprecated alias **survives** (only `useYarnRunner` dies, with the hook); SvelteKit host untouched.
- No runtime behavior lives in the adapter (verified before plotting): core `compile/`, `runtime/`, `markup/`, `model/`, `parse/` have zero React imports; `scheduleContinue` and `reshapeView` live inside `src/react/`. The adapter is pure presentation layer.
- This effort **supersedes** settled clauses of earlier efforts: `framework-agnostic-consumption`'s "Out of scope: React adapter API changes … adapter's surface is settled" and the React-subpath parts of `direct-import-implementation` issues 08 (browser acceptance harness) and 09 (docs). Do not re-open those maps; record deviations here.
- The two-axis review of the open `.scratch/` efforts has landed (findings appended to the prior efforts' issue files under `## Comments`). Ticket 01 must consult it for anything touching the adapter before deletion starts.
- The browser demo is the **acceptance harness** for the public surface and the plugin (direct-import 08): the vanilla rewrite must keep that role — consumes `dist/` + the plugin + the shared `examples/content/` project, built end-to-end by a test.
- The Next.js host's SSR `loadYarnProject` path works and stays (consumption spec, out-of-scope ruling). Only the client interaction layer changes.
- One ticket resolved per session; research tickets exempt.
- Skills every session should consult: `grilling` (ticket 03), `domain-modeling` (glossary fallout in ticket 06).

- The generic loader contract / webpack-loader story (settled by `direct-import-implementation`; untouched here).
- Reworking the SSR hosts' `loadYarnProject` deployment-data path.
