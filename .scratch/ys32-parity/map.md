# Map: Yarn Spinner 3.2 parity audit

Label: wayfinder:map

## Destination

A complete, evidence-backed gap analysis of yarn-spinner-runner-ts against live Yarn Spinner 3.2.2, plus the decision set the parity spec depends on (nonstandard-extension verdicts, runtime API shape, saliency / smart-variable / markup / diagnostics / localisation scope, conformance harness) — enough information to write the 3.2 parity spec in a follow-up session. The spec itself is **not** written by this map.

## Notes

- **Domain**: TypeScript reimplementation (parser / compiler / runtime) of Yarn Spinner 3.x. React adapter exists but is out of scope; the browser demo (`npm run demo`) stays green and serves as the acceptance harness.
- **Live target**: Yarn Spinner **3.2.2** (Aug 2026). Re-check for point releases at spec time.
- **Parity contract**: language + behavior parity (a 3.2 `.yarn` script parses, compiles, and runs identically). No protobuf/`Program` artifact compatibility.
- **Divergence policy**: per-conflict decisions; default posture is "conform to upstream specs". **Breaking API changes are allowed** (pre-1.0).
- **Conformance bar**: upstream's own `.yarn` test fixtures serve as golden tests, in addition to the repo's 46 existing tests.
- **Diagnostics are in scope** (YS-code-aligned error/warning system).
- **Working style**: serial sessions with the maintainer; priority tiers proposed by the agent, reshuffled by the maintainer. Never resolve more than one ticket per session (research excepted).
- **Skills**: `grilling` + `domain-modeling` for decision tickets; `research` skill for research tickets.
- **Baseline research (charting session)**: [repo audit](research/repo-audit.md) · [3.2.2 census](research/ys322-census.md). Corrections to folklore: upstream has no `<<visit>>`/`<<unset>>` (fork matches upstream there); upstream has no ternary (fork README is wrong); `docs/compatibility-checklist.md` is stale.

## Decisions so far

- [YarnSpinner-Rust reference study](issues/02-rust-reference-study.md): YarnSpinner-Rust v0.9 is a **Yarn 2.x implementation** (maps to .NET 2.5.0 — zero saliency/smart-variables/enums/node-groups/once/detour/YS00xx), so it's a porting-strategy reference, not a 3.2.2 feature reference; it transliterated the .NET instruction-stream VM (evidence the instruction-stream shape is the portable contract; this repo's tree IR is the outlier), uses a **pull-based runtime API** (`continue_() -> Vec<DialogueEvent>` — handlers become return values, `PrepareForLines` demoted to opt-in `LineHints`), proves the golden-fixture harness pattern (gitmodules + ported TestBase over upstream `.yarn` fixtures), splits errors-in-`Err`/warnings-in-`Ok`, has no stable diagnostic codes, and warns off ANTLR-generated-parser pinning and 2.x transliteration. Full findings: [research/rust-reference-study.md](research/rust-reference-study.md).
- [Localisation mechanics deep dive](issues/11-localisation-mechanics.md): upstream splits localisation into three layers — core compiler assigns line IDs + produces a string table; CSV strings files and `.yarnproject` are **host-plugin artifacts, never compiler inputs**; core runtime is deliberately string-table-unaware (hosts resolve text per locale; Rust injects a `TextProvider`). For a TS library without Unity project files: compiler layer + small CSV module, **no `.yarnproject` equivalent** — program + string-table compile API (full / strings-only modes) suffices. Contract: `Map<lineID, {text, file, node, lineNumber, isImplicitTag, metadata, shadowLineID}>`; implicit IDs = `line:` + CRC32(file+node+count) (census/audit correction: not a global counter); `#shadow:` compile-time only; `lock` = first 8 hex SHA-256 of base text; CSV `comment` column = line hashtag metadata, **not** `///` doc comments (second census correction — `///` attaches to declarations only in 3.x). `ILineTagGenerator` seam worth shipping; runtime recommendation: injectable text-provider seam (`setLanguage`) — slots into the runtime-API-shape decision. Full findings: [research/localisation-mechanics.md](research/localisation-mechanics.md).
- [Diagnostics catalog (YS0001–YS0047)](issues/09-diagnostics-catalog.md): authoritative YS00xx registry is per-code markdown in the upstream repo @ 3.2.2, not the docs page (which is stale/wrong on severities); of the catalog, 12 codes adoptable as-is, 10 with adjusted triggers, 10 deferred, 14 N-A; YS0002/YS0001 are dead codes (type errors now YS0050); registry extends past YS0047 (YS0048, YS0050–YS0053, YS0060–YS0064); cheapest high-value first tranche: YS0005 + YS0030/YS0031/YS0012. Full catalog: [research/ys322-diagnostics.md](research/ys322-diagnostics.md).

- [Inventory upstream conformance fixtures](issues/01-upstream-conformance-fixtures.md): the .NET repo's `Tests/` corpus @ 3.2.2 is the sole golden set (Rust adds zero — it re-consumes the same files via submodule); vendor `YarnSpinner@v3.2.2:Tests/` (~40 KB, tag-pinned); assertions live in sidecar **`.testplan` DSL** files run by a strict event-stream step-lock with composed-text comparison — TS harness needs a vendored copy, a ~150-line testplan parser, and a TestBase port; do **not** copy the Rust reader (obsolete pre-backtick format). Coverage: saliency, node groups, once, smart variables, enums, detour/return, shadow lines, visited-tracking; **no fixture coverage** for markup parsing, PrepareForLines, localisation/CSV, line-tag generation (port inline C# tests instead). Harness functions (`assert`, `dummy_*`…) are part of the contract; nothing requires Unity. Phasing: (1) vendor + ParseFailures must-fail loop, (2) testplan parser + runner for the 32 pairs, (3) diagnostic-definition examples for exact YSxxxx codes. Full findings: [research/upstream-fixtures.md](research/upstream-fixtures.md).
- [Nonstandard extension verdicts](issues/03-nonstandard-extension-verdicts.md): **`[if expr]` option conditions — drop outright** (upstream `<<if expr>>` on the option line only; migration note + error diagnostic), **`{if}` inline text blocks — drop** (collides with upstream `{expr}`; migrate to line conditions), **`&css{}` — removed from core** (styling consumer-side), **`scene:` header — upstream-compatible passthrough, no action** (scene system stays with React, out of scope), **ternary — README fix only**, **every-command `CommandResult` — conform** (state commands internal; CommandHandler gets non-state commands only). Spec deletes two syntaxes, removes one extension, conforms one behavior.

- [Runtime API shape](issues/05-runtime-api-shape.md): Rust-style **pull** model — `continue() -> DialogueEvent[]` (chosen because the golden-test TestBase contract asserts a strict event stream); upstream event vocabulary camelCased (`Line`, `Options`, `Command`, `NodeStart`, `NodeComplete`, opt-in `LineHints`, `DialogueComplete`); **pluggable VariableStorage** (bool/number/string) + in-memory default; `once`-state as **generated variables in storage** (fixes global-state bug); **Library-style registry** for variadic functions + command handlers; **`advance()` dropped** for `continue()`/`selectOption(index | NoOptionSelected)`/`setNode()`/`stop()`; **`NoOptionSelected` fall-through adopted**; **injectable text-provider seam built now** (Line events carry IDs; provider resolves text, `setLanguage` later).
- [Spec roadmap & implementation ordering](issues/16-spec-roadmap-ordering.md): **five dependency-driven phases** — 0 conformance foundation (vendor fixtures + must-fail loop) → 1 compiler & language core (exit: 32 fixtures compile w/ expected diagnostics) → 2 runtime & VM (exit: testplan runner green on 32 pairs) → 3 compiler surface & localisation → 4 migration & ship (demo + docs + release); exit criteria per phase from the fixture corpus; **one 0.2.0 "3.2 parity" release** (breaking API lands together); spec session re-checks for point releases >3.2.2 and records the targeted version. **Map complete — all decisions for the spec are made.**
- [Compiler multi-file model](issues/15-compiler-multi-file-model.md): **`compile(files: CompileFile[])`** — array of `{name, source}`, no globs/IO in the library; **external declarations API** (conflicts → YS diagnostics); **all four CompilationTypes** (Full, StringsOnly, DeclarationsOnly, type-check-only); **Library accepted at compile time for signature checking**, runtime keeps its own; result shape mirrors upstream camelCased (`{program, stringTable, declarations, diagnostics, fileTags, containsImplicitStringTags, userDefinedTypes}`), program = versioned JSON.
- [IR/VM redesign decision](issues/14-ir-vm-redesign.md): **TS-idiomatic instruction-stream stack VM**; tree IR retires (AST stays as front-end); **expressions compile to bytecode** (string evaluator becomes codegen); program = **versioned JSON** with `languageVersion` (not protobuf); **jumps = instruction indices** (labels resolved in compiler pass); VM machinery per prior decisions — per-node line-ID table → opt-in `LineHints`, dedicated saliency-candidate ops, detour/return call stack (jump clears it), generated variables for tracking/once/saliency state.
- [Visit tracking & the `tracking:` header](issues/13-visit-tracking-header.md): visit state as **generated variables in VariableStorage** (reset with the store, consistent with once/saliency); visits recorded **on node return** (pre-visit count during the node); `tracking: never` suppresses recording, `tracking: always` = accepted no-op (default behavior); node-group visits **aggregate under the shared title** (3.1 conform); IR representation deferred to ticket 14.
- [Localisation scope decision](issues/12-localisation-scope.md): **full compiler layer first spec** (CRC32 implicit IDs, `#line:` verbatim, `#shadow:` validation YS0042/43/44, string table as compile output); **CSV module** (8-column format, SHA-256 locks, hashtag-metadata comments) + **strings-only compile mode**; line-tag generator seam + Random/Descriptive built-ins; **no `.yarnproject` equivalent**; **CSV-backed translation provider ships at launch** (`setLanguage`) over the ticket-05 text-provider seam. Compiler multi-file fog graduated to [15](issues/15-compiler-multi-file-model.md).
- [Diagnostics decision](issues/10-diagnostics-decision.md): **collect by default** + optional strict throw-on-first-error; upstream `Diagnostic` shape (`code`/`severity`/`message`/`file`/`range`/`context` — YS0005, fixes missing line/col); first-spec target = the **22 adoptable YS-codes** incl. YS0005/0030/0031/0012/0032/0045/0050/0063, deferred codes join as features land; **3.2.2 per-code markdown registry is authoritative** (docs stale); runtime surface = `logError`/`logDebug` option callbacks.
- [Markup scope](issues/08-markup-scope.md): **upstream split adopted** — compiler stores raw lines; runtime `LineParser` does substitutions → markup (`MarkupParseResult` with attribute positions, `DeleteRange`, `TextForAttribute`); replacement markers `[select]`/`[plural]`/`[ordinal]` in first spec via `Intl.PluralRules` (+ `ReplacementMarkerResult` invisible-char counts); parser completeness in (close-all `[/]`, property shorthand, self-closing whitespace-trim + `trimwhitespace=false`, attribute types); implicit `[character name=]` marker replaces the regex speaker slice; markup diagnostics fold into compilation (YS0063, via ticket 10); minimal custom-processor registry; styling tags stay opaque data.
- [Smart variables & enums semantics](issues/07-smart-variables-enums.md): smart variables **full upstream semantics** (read-only YS0030, recompute-on-access, cycle detection YS0045, `tryGetSmartVariable`); regex heuristic and set-downgrades-smart removed. `as Type` = **compile-time validation + declarations metadata**, runtime naturally JS-typed. Enums **fully adopted** (uniform raw values, auto-numbering, same-enum `==`/`!=` restriction, `.Case` shorthand); runtime representation = plain raw values with compile-time enum identity. **Amended**: host-defined enums promoted into scope via the external declarations path (EnumTypeBuilder equivalent).
- [Saliency & node groups scope](issues/06-saliency-node-groups.md): **full machinery** — complexity scoring + all four strategies, **Random BLRV default** (forced by fixture `saliency:` steps); pluggable two-method strategy interface day one; `<<set_saliency>>` command in; **line groups `=>` in the first spec** (ticket 04 delegation); node-group conformance errors (member without `when:`, YS0032 duplicate subtitle) land via the diagnostics contract; query APIs in (`has_any_content`, `isNodeGroup`, `getSaliencyOptionsForNodeGroup`, `hasSalientContent`); saliency history as **generated variables in VariableStorage**.
- [Statement/line parity phasing](issues/04-statement-parity-phasing.md): first spec gets line-level `<<if>>`/`<<once>>`/`<<once if>>`, `<<call>>`, compound assignment, `<<return>>` + detour interaction, built-in `<<wait>>` (consumer-timed) + working `<<stop>>` (halts; fixes no-op bug), escapable `:`, `subtitle` (+YS0032 group-duplicate check), and `$`-prefix strictness (bare-var normalization removed, with diagnostic). `tracking: always|never` confirmed wanted and promoted to its own ticket [13](issues/13-visit-tracking-header.md) (blocked by runtime API shape); line groups `=>` delegated to the saliency ticket (full machinery ⇒ `=>` in).
